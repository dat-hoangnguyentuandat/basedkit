# Frontend, Hooks And Shortcodes

## Frontend Contract

Expose endpoint/options through `data-*` or JSON generated by the plugin. Use CSRF for web forms, prefix selectors with the plugin namespace and initialize after DOM ready when needed. Prevent duplicate initialization when multiple widgets render.

```blade
<form data-my-plugin-form data-submit-url="{{ route('my-plugin.submit') }}">
  <div data-my-plugin-status aria-live="polite"></div>
</form>
```

## Hooks

Register from `plugins/{slug}/src/Plugin.php` through `HookManager`. Core hooks include `cms.widget.rendered`, `cms.contact.before_store` and `cms.contact.after_store`; inspect signatures before using them.

## Shortcodes

Register through `ShortcodeManager` in the provider. Use lowercase tags with `_`/`-`, escape user attributes and return HTML strings. Unknown shortcodes remain unchanged. Use `cms_content()` or `cms_shortcodes()` for admin-authored content.

Core examples include `[button]`, `[zalo_chat]`, `[map]`, `[contact_form]`, `[lead_form]`, `[product_list]`, `[gallery]` and `[pricing_table]`; verify current implementation before relying on optional behavior.

Test shortcode output with `php artisan tinker` after registering it. Do not run unbounded queries from a shortcode.
